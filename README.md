# Binsity Project
This is the project about trash classfication. 

### Installation of the Virtual environment

```bash
uv venv --python 3.11 --system-site-packages
```

Use `--system-site-packages` to include and be able to see packages installed globally
vias the system package manager (apt) (Ex: underlying C/C++ libraries)

In the Raspberry Pi (Debian OS) environment uses
``bash
uv pip install .[pi]
``
Since there is a library `picamera2` for the raspi cam only available in the Raspberry Pi

In the NVIDIA GPU's environment (has CUDA in it). Use this installation

```bash
uv pip install .[gpu]
```

### Activating the virtual environment
At the working directory use this command:
```bash
source .venv/bin/activate
```

### Explanation of the directory

Below is a breakdown of the key files and folders in this project:

**Core Code & Notebooks**

- `raspberrypi_code/`: Contains the source code specifically designed to run on the Raspberry Pi hardware (edge deployment).
- `main.py`: The main entry point script for running the application.
- `training.ipynb`: Jupyter notebook used for training the initial model on the TrashNet dataset.
- `fine-tuning.ipynb`: Jupyter notebook used for fine-tuning the model (transfer learning) on specific/custom datasets.
- `comparing_images.ipynb`: A notebook for visualization, likely used to compare input images or analyze model predictions side-by-side.
- `download_dataset.py`: Utility script to automatically download and prepare the required datasets (e.g., TrashNet) for training.

**Configuration & Environment**

- `pyproject.toml`: The main configuration file for the project. It defines build requirements and dependencies (managed by uv).
- `.venv/`: The virtual environment directory created by uv containing all installed libraries.

**Data & Outputs**

- `checkpoints/`: Stores saved model weights (state dicts) generated during the training or fine-tuning process.
- `tnsboard/`: Contains TensorBoard log files for visualizing training metrics (loss, accuracy, etc.) over time.
- `output/`: General directory for build artifacts or results generated by the script (Specifically, the visualization of the model)
- `images/`: Storing the Binsity Dataset (taken from the TrashBin)
